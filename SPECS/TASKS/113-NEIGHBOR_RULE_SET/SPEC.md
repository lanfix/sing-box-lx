## Why

Роутер раздаёт обход блокировок устройствам LAN. Любое устройство, получившее обход, может его
выдать: приложение на нём периодически открывает заблокированный ресурс и сообщает результат.
Защита — профили доверия: новое устройство не получает обход, пока его не одобрят, гостевое —
идёт как у провайдера. Списки устройств меняются часто (одобрение, перевод в карантин), и делать
это нужно без перезапуска ядра.

Апстрим 1.14 даёт `source_mac_address`/`source_hostname` только в правилах конфига; в
`DefaultHeadlessRule` их нет. Значит, каждое изменение списка — новый конфиг и перезапуск: рвутся
соединения всех устройств, а перезапуск по каждому одобрению неприемлем.

Критерии §3.1: (а1) запрос конфигуратора роутера; (а2) в апстриме нет, в 1.15-alpha.10 тоже;
(а3) три апстримных файла и 15 строк против перезапуска ядра на каждое изменение списка;
(б) новые файлы + маркеры, без тега (поля без задания — апстрим).

## Что сделано

- `source_mac_address`, `source_hostname` в headless-правиле формата `source`, матчинг апстримными
  `SourceMACAddressItem` / `SourceHostnameItem` (те же, что в правилах конфига).
- Если в контексте есть роутер и `NeedFindNeighbor()` ложно — ошибка
  ``… rule items in rule-set require `route.find_neighbor` ``. Без роутера в контексте (`sing-box
  rule-set match` и подобные) проверка не делается.
- `srs.Write` отказывает на правиле с этими полями: двоичной записи нет, молча выброшенное
  условие расширило бы правило.
- Версия rule-set не меняется (номера версий и записей `.srs` — апстримные).

## Критерии приёмки

- [x] Юниты: разбор `source`-формата; совпадение по MAC в разных записях; по имени; И с
  `source_ip_cidr`; `invert` в логическом правиле; отказ без `find_neighbor` (в т.ч. внутри
  логического правила); без роутера в контексте — без проверки; отказ `srs.Write`
  (обычное и логическое правило).
- [x] `go vet` и `go test` с тегами lx: `./route/... ./common/srs/ ./option/ ./cmd/sing-box/`.
- [x] `make -f Makefile.lx lx-build`; `sing-box check` принимает пример и отвергает его без
  `find_neighbor`; `sing-box rule-set compile` отказывает.
- [x] e2e: docker-сеть, ядро + два клиента с заданными MAC, `local` rule-set. Первый MAC → reject,
  второй → direct; правка файла внутри контейнера → роли поменялись при одном старте ядра.
  Перечитывание без `find_neighbor` → ошибка в журнале, прежний набор остаётся.
- [ ] Полевой прогон на роутере (192.168.50.6) с конфигуратором.

## Условие снятия

Апстрим добавил `source_mac_address`/`source_hostname` в `DefaultHeadlessRule`. Тогда снимаются
поля, вызов и новый файл; запрет компиляции — если апстрим ввёл двоичную запись. Предложение
апстриму — отдельный PR в `SagerNet/sing-box` (`testing`) с полной формой: двоичная запись,
версия rule-set, автовключение поиска соседей по метаданным rule-set.
