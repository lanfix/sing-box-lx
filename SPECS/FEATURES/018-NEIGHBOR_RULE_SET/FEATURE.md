# FEATURE 018 — NEIGHBOR_RULE_SET — правила по устройствам в rule-set

| Поле | Значение |
|------|----------|
| Тип | Продуктовая фича |
| Build-tag | — (новые поля без задания ведут себя как апстрим) |
| Состояние | I — [113](../../TASKS/113-NEIGHBOR_RULE_SET/SPEC.md): код, юниты, сборка `lx-build`, e2e в docker-сети с подменой MAC; на роутере не гонялось |

## Назначение

Роутер с ядром решает, какой трафик каких устройств LAN идёт в туннель. Апстрим 1.14 умеет
различать устройство-источник по MAC и имени из DHCP, но только в правилах маршрутизации и DNS
самого конфига: чтобы поменять список устройств, нужно применить новый конфиг, а это перезапуск
ядра и разрыв всех соединений всех устройств.

Фича переносит те же условия в rule-set формата `source`. Rule-set перечитывается сам (`remote`
по `update_interval`, `local` по изменению файла), поэтому интерфейс роутера переносит устройство
между группами — доверенные, гостевые, карантин — без перезапуска. Запрос — конфигуратор роутера
(профили доверия устройств: новое устройство не получает обход, пока его не одобрят).

## Контролируемые параметры

| Ключ | Где | Тип | Значение |
|------|-----|-----|----------|
| `source_mac_address` | правило rule-set формата `source` | строка или список | MAC устройства-источника, любая запись `aa:bb:…` / `AA-BB-…` |
| `source_hostname` | правило rule-set формата `source` | строка или список | Имя устройства-источника из аренд DHCP |
| `route.find_neighbor` | конфиг (апстрим) | bool | Обязателен для rule-set с этими полями |
| `route.dhcp_lease_files` | конфиг (апстрим) | список | Источник имён и MAC, как в апстриме |

Версия rule-set не меняется: поля принимаются в любой версии формата `source`.

## Входы / Выходы

- **Вход:** rule-set формата `source` (`inline`, `local`, `remote`) с новыми полями.
- **Выход:** правило rule-set совпадает, когда MAC/имя соединения, найденные апстримным поиском
  соседей, есть в списке. Ссылка на rule-set из правил маршрутизации и DNS работает как для любого
  другого поля.
- **Отказ:** rule-set с новыми полями без включённого поиска соседей не загружается; компиляция
  в двоичный `.srs` отказывает.

## Data flow

1. Ядро стартует с `route.find_neighbor: true`: апстримный поиск соседей подписан на таблицу
   соседей и файлы аренд.
2. Rule-set загружается или перечитывается; правила с новыми полями собираются из апстримных
   матчеров MAC и имени.
3. Новое соединение: апстрим заполняет MAC и имя источника до сопоставления правил.
4. Правило со ссылкой на rule-set совпадает по списку устройств. Новая версия списка действует
   для новых соединений с момента перечитывания rule-set.

## Правила и гарантии

- **P1. Без перезапуска.** Изменение списка устройств в `remote`/`local` rule-set применяется
  перечитыванием rule-set; ядро и соединения других устройств не трогаются. Свидетель: e2e 113 —
  смена MAC в `local` rule-set переключила reject между двумя клиентами при одном старте ядра.
- **P2. Громкий отказ вместо тихого несовпадения.** Если поиск соседей не включён, rule-set
  с новыми полями отвергается (старт — ошибка, перечитывание — ошибка в журнале и прежний набор).
  Мутация: rule-set принимается и молча ничего не матчит (класс апстримного #4341).
- **P3. Условие не теряется.** Двоичный `.srs` не умеет новые поля, поэтому компиляция падает,
  а не выбрасывает условие и не расширяет правило.
- **P4. Апстрим байт в байт без полей.** Rule-set и конфиг без новых полей ведут себя как апстрим;
  матчинг и поиск соседей — апстримные.

## Границы

- Двоичный формат `.srs` и новая версия rule-set — не делаем: номера записей и версии принадлежат
  апстриму. Полная форма предлагается апстриму отдельным PR.
- Автовключение поиска соседей по содержимому rule-set — не делаем (правка роутера апстрима);
  достаточно `route.find_neighbor`.
- Определение приложения на устройстве, защита от подмены MAC — вне фичи.

## Особенности сопровождения

- **Условие снятия:** апстрим добавил `source_mac_address`/`source_hostname` в headless-правила
  (поле в `DefaultHeadlessRule`). Тогда наши поля и матчинг снимаются в пользу апстримных;
  если апстрим заодно введёт двоичную запись — снимается и запрет компиляции.
- Мерж апстрима, тронувший `DefaultHeadlessRule` или сборку headless-правила, — проверить, что
  маркеры `lx:begin neighbor-rule-set` на месте и тесты 113 зелёные.
